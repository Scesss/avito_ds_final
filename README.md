# Candidate generation для Avito

## Задача

Для каждого поискового запроса нужно выбрать до 50 объявлений из
`benchmark_items.parquet`. Качество оценивается по Recall@50

## Данные

- `train.parquet` — пары запрос - выбранное объявление
- `benchmark_queries.parquet` — запросы, для которых строится ответ
- `benchmark_items.parquet` — объявления, среди которых идёт поиск

В запросе использую текст, параметры, категорию и локацию. В объявлении использую
`item_title_raw`, `item_infm_params_text`, `item_description_raw`, категорию и локацию

## Как работает решение

1. Строю два TF-IDF индекса по корпусу объявлений: по словам и по символьным
   фрагментам длины 3–5. Символьный индекс помогает при окончаниях и опечатках
2. Заголовок объявления повторяю три раза, параметры — два раза, описание — один
   раз. Поэтому короткий заголовок сильнее влияет на сходство
3. По `train` строю таблицу частот: какие локации объявлений обычно выбирают при
   каждой локации поиска. Это учитывает связанные территории с разными ID
4. Для каждого заголовка собираю запросы, по которым раньше выбирали объявления с
   таким заголовком. Это помогает связать разные формулировки одной услуги
5. Объединяю текстовый балл, историю формулировок, географию и категорию и беру 50
   объявлений с максимальным баллом

Используются простые алгоритмы: TF-IDF, косинусное сходство и частотные эвристики.
Нейросетей, внешних API нет

## Проверка

Часть запросов из `train` откладывается для локальной проверки. Вся история
проверяемого запроса удаляется из обучения. Веса выбираются на dev-части, а test
используется один раз для сравнения

Лучший результат Recall@50  — `0.803390`
